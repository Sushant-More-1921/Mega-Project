## Interpretation and limitations

- Project holdout metrics use a stratified random 20% split (random seed 42). They measure performance on the project data distribution, not an independently collected civic dataset.
- Priority labels in `priority_complaints.csv` were generated by the project's keyword rules. Priority scores therefore measure agreement with those pseudo-labels, not verified urgency.
- The NYC check tests one row per unique `(complaint_type, descriptor)` pair in the downloaded sample. The expected project category is mapped from the NYC service type, and the model sees only the descriptor text. NYC does not provide equivalent project priority labels. Garbage may have no support in the sample.
- The NYC check is a useful domain-shift stress test, not a representative estimate of model quality on free-form complaints.
- Voice, image, chatbot, and duplicate-detection dependencies require separate local model/service setup; this report does not claim those integrations are live-tested. API unit tests mock external model and backend calls.

## Reproduce

From `ai-service`, run:

```powershell
.\venv\Scripts\python.exe -m evaluation.evaluate_ai
.\venv\Scripts\python.exe -m unittest discover -s tests -v
```

External data: NYC Open Data, 311 Service Requests from 2020 to 2025, dataset `erm2-nwe9`: [data.cityofnewyork.us](https://data.cityofnewyork.us/resource/erm2-nwe9.json). The saved sample is `nyc_311_test.csv`; predictions are in `nyc_311_predictions.csv`.
